# ระบบจัดตารางสอนอัตโนมัติ (ต้นแบบซ้อมแข่งทักษะ)

โปรเจกต์ซ้อมแข่งขันทักษะวิชาชีพ ปวส. สาขาเทคโนโลยีปัญญาประดิษฐ์ หัวข้อ "ระบบจัดตารางสอนอัตโนมัติ"
ทีม 2 คน ซ้อมระดับภาค (ประมาณ 23–27 พ.ย. 2569 ที่กระบี่) ตั้งเป้าไปต่อระดับชาติ
วันแข่งได้โจทย์และชุดข้อมูล CSV ใหม่ และต้องลง Windows ใหม่ทั้งหมด ใช้ผู้ช่วย AI ได้

## วิธีพูดกับผู้ใช้
- ผู้ใช้เป็นนักเรียน ปวส. ตอบเป็นภาษาไทย เข้าใจง่าย ทีละขั้น
- ทุกครั้งที่เขียนโค้ด อธิบายเหตุผลสั้น ๆ เพราะกรรมการถามเชิงลึกว่าทีมเข้าใจโค้ดหรือไม่

## โครงสร้างไฟล์
| ไฟล์ | หน้าที่ |
| --- | --- |
| `engine.js` | แกนระบบ ไม่ขึ้นกับหน้าเว็บ: config, ตัวสุ่ม seed (mulberry32), อ่าน/เขียน CSV, ข้อมูลตัวอย่าง 4 ชุด, inputCheck, ตัวจัดตาราง, ตัวตรวจ 15 ข้อ, metrics, checkPlacement (ย้าย/สลับ) |
| `app.js` | หน้าจอทั้งหมด: ล็อกอิน 3 Role, นำเข้า/แก้ข้อมูล, ตั้งค่า, จัดตาราง (Web Worker), ตรวจ 15 ข้อ, ตารางสอนลากย้าย, สถิติ, เวลาไม่สะดวก, บัญชีผู้ใช้ |
| `body.html` | โครง HTML ของทุกหน้า (section.view) |
| `app.css` | สไตล์ ใช้ token สีใน `:root` และรองรับโหมดมืด |
| `build.py` | รวมไฟล์ → `index.html` (Artifact) และ `docs/index.html` (เว็บเต็ม เปิดเองหรือขึ้น GitHub Pages) |
| `test.js` | ทดสอบแกนระบบด้วย Node |

## คำสั่ง
```
node test.js        # ทดสอบแกนระบบ: 4 ชุดข้อมูล, ใส่ข้อผิดให้ตัวตรวจจับ, ย้าย/สลับต้องผ่านตัวตรวจ
python build.py     # สร้าง index.html และ docs/index.html
```
เปิด `docs/index.html` ในเบราว์เซอร์ได้เลย บัญชีทดลอง: `admin/admin123`, ครู `t01`… `/1234`, นักเรียน `g01`… `/1234`

## กฎที่ต้องทำตาม (สำคัญ)
1. **ห้าม hardcode** รหัสวิชา รหัสห้อง รหัสครู หรือช่วงเวลา ให้อ่านจาก `DEFAULT_CONFIG` / หน้าตั้งค่าเท่านั้น
2. **ห้ามใช้ `Math.random()` ในตัวจัดตาราง** ใช้ `mulberry32(seed)` ให้รันซ้ำได้ผลเดิม
3. คาบที่จัดไม่ลงต้องบันทึกพร้อมเหตุผลและวิธีแก้เสมอ ห้ามข้ามเงียบ ๆ
4. ตัวตรวจ (`validate`) ต้องแยกจากตัวจัดตาราง ทุกการแก้ตารางต้องตรวจซ้ำ
5. แยกประเภทวิชาจาก **ชื่อวิชาก่อน** (กิจกรรม → โฮมรูม → IOT) แล้วค่อยดูรหัสวิชาสามัญ 20000/30000 เพราะวิชากิจกรรมบางวิชามีรหัส 20000
6. วิชาสามัญเรียนรวม 2 กลุ่ม = หลายแถวใน output ที่ครู ห้อง คาบเดียวกัน ตัวตรวจข้อ 6, 7 ต้องยกเว้นกรณีนี้
7. ข้อ 10 (ประชุมหัวหน้า) และ 12 (กิจกรรม) ให้หาช่องจาก start/end ของ timeslot ไม่ยึดเลขคาบ
8. คอมเมนต์และข้อความ error เป็นภาษาไทย บอกว่าผิดอะไรและแก้อย่างไร
9. JavaScript ธรรมดา + HTML/CSS ไม่ใช้ framework ไม่มี build step นอกจาก `build.py`
10. หลังแก้ `engine.js` ให้รัน `node test.js` ทุกครั้ง หลังแก้หน้าเว็บให้รัน `python build.py` แล้วเปิดดูจริง

## Dataset ตามโจทย์ (หัวคอลัมน์ต้องตรงทุกตัวอักษร)
room(room_id, room_name, room_type) · student_group(group_id, group_name, student_count, advisor) · subject(subject_id, subject_name, theory, practice, credit) · teacher(teacher_id, teacher_name, role) · timeslot(timeslot_id, day, period, start, end) · teach(teacher_id, subject_id) · register(group_id, subject_id) · output(group_id, timeslot_id, subject_id, teacher_id, room_id) 1 แถว = 1 คาบของ 1 กลุ่ม

## เงื่อนไข 15 ข้อ (จากรอบระดับชาติของรุ่นพี่)
1 คาบ = theory+practice · 2 คาบ 5 พัก · 3 จำนวนวิชา = ที่ลงทะเบียน · 4 คาบรวมครบ · 5 ไม่เกิน 10 คาบ/วัน · 6 ครูไม่ซ้อน · 7 ห้องไม่ซ้อน · 8 ครูสอนเฉพาะวิชาใน teach · 9 ทฤษฎีห้องทฤษฎี วิชามีปฏิบัติห้ามห้องทฤษฎี · 10 Manager ประชุมอังคาร 15–16 · 11 โฮมรูม ≥ 1 คาบ · 12 กิจกรรมพุธ 15–17 · 13 วิชาสามัญเรียนรวม 2 กลุ่ม · 14 IOT ห้อง R6201 เท่านั้น · 15 เลี่ยงทฤษฎีหลังคาบ 9 (soft)
เพิ่มเติมจากโจทย์: ครูไม่สอนในเวลาที่แจ้งว่าไม่สะดวก (`teacherUnavailable`)

## อัลกอริทึม
- ชั้น 0 baseline: ตามลำดับไฟล์ ลงช่องแรกที่ว่าง (ไว้เทียบ)
- ชั้น 1 Greedy + Heuristic: จัดวิชายากก่อน (กิจกรรม → โฮมรูม → IOT → สามัญ → ปฏิบัติ → ทฤษฎี) เลือกช่องคะแนนโทษต่ำสุด สุ่มด้วย seed รันหลายรอบเก็บดีสุด
- ชั้น 2 วงรอบซ่อม plan-act-check: ย้ายบล็อกที่ขวาง ≤ 2 บล็อก ถ้ายังไม่ได้ให้แบ่งบล็อก ตรวจซ้ำ ย้อนกลับถ้าแย่ลง
- แบ่งคาบ: ค่าเริ่มต้น `blockMax` (ปฏิบัติ 4, ทฤษฎี 2) เช่น 5 คาบ → 3+2 หรือกำหนดรายวิชาใน `splitOverride`

## สถานะ
ทำแล้ว: ทุกอย่างข้างบน + ลากย้าย/สลับพร้อมสีบอกช่อง, แบ่ง/รวมบล็อก, เลิกทำ, แก้ข้อมูลบนหน้าเว็บ, พรีวิวการนำเข้า, Export (Excel/CSV/HTML พร้อมพิมพ์), RBAC 3 Role, รหัสผ่าน SHA-256 + salt

ยังไม่ได้ทำ (เรียงตามความสำคัญ):
1. ต่อฐานข้อมูลจริงแบบ BaaS (แนะนำ Supabase หรือ Firebase แบบที่รุ่นพี่ระดับชาติใช้) แล้ว deploy ขึ้น GitHub Pages ให้มี URL ข้อมูลตอนนี้หายเมื่อรีโหลด หน้าเว็บเป็น HTML/JS อยู่แล้ว ไม่ต้องเปลี่ยนไปใช้ PHP
2. **ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์** (Supabase RLS หรือ PHP session) ตอนนี้ตรวจในเบราว์เซอร์อย่างเดียว
3. ซ้อมกับไฟล์ CSV ชุดจริงของรุ่นพี่ แล้วยืนยันจุดที่ไม่ชัด (ค่า room_type, ชื่อวิชาโฮมรูม/กิจกรรม/IOT, รูปแบบ day)
4. แถวสรุปบนตารางผลแต่ละ seed (ต่ำสุด/เฉลี่ย/สูงสุด, ไม่ชนกี่ seed)
5. ระดับชาติ: Simulated Annealing ลดคะแนนโทษ + LLM อธิบายสาเหตุที่จัดไม่ลงเป็นภาษาไทย
6. คู่มือผู้ใช้ และอัปเดตสคริปต์นำเสนอให้ตรงตัวเลขล่าสุด
